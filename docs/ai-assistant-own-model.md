# 用自己发布的推理服务作为 AI 助手的模型

AI 助手默认调用外部的大模型接口。如果你已经在平台上部署并发布了推理服务，可以让 AI 助手直接用它，不需要新的界面或配置项，只用现有的 AI 设置。本文面向管理员，按顺序操作即可。

## 前提

- 当前集群已安装网关，并且至少有一个已发布的推理服务（见“模型服务”下的“网关”和“推理服务”页面）。
- 该推理服务的模型支持工具调用（function calling）。AI 助手靠工具调用来查看资源、日志和指标，没有它就无法使用任何工具。
- MPlatform 服务端能访问网关的地址（AI 请求由服务端发出，不是浏览器）。

## 第 1 步：为推理服务打开工具调用

在“模型服务 / 推理服务”中新建服务，或打开已有服务点“修改”，在“引擎参数”分组里填写“工具调用解析器”：

- 选择与模型匹配的解析器。列表里是常用值，旁边标注了对应的模型，镜像支持的其他名字也可以直接填写。例如 vLLM 上 Qwen2.5 / Qwen3 用 `hermes`，SGLang 上用 `qwen25`；两个引擎的名字不同，以列表为准。
- 平台会把它转成引擎启动参数：vLLM 为 `--enable-auto-tool-choice --tool-call-parser <名称>`（两个参数缺一不可，平台会一起加上），SGLang 为 `--tool-call-parser <名称>`。你不需要手写这些参数。
- 嵌入（Embedding）模型没有这个字段，也不能作为 AI 助手的模型。
- 保存后 Pod 会重建，只有 1 个副本的服务在新 Pod 就绪前会中断。等服务状态恢复正常再继续。

如果你更愿意手写，也可以把上述参数填到同一表单的“高级配置”里的“额外参数”，效果相同，但不要两处重复填写。

## 第 2 步：发布并准备调用方

1. 在推理服务页面点“发布到网关”，记下“模型名称”。
2. 在“网关”页面的“调用方”里添加一个专用调用方，例如 `ai-assistant`：
   - “可访问模型”里选上这个模型。没有选任何模型的调用方，所有请求都会被拒绝。
   - 按需设置“每分钟 Token 上限”和“总额度”。
3. 在调用方列表里查看该调用方的 API Key（`sk-` 开头）。
4. 在“网关”页面记下“访问地址”，形如 `http://<节点地址>:<NodePort>`。

## 第 3 步：填写 AI 设置

打开“设置 / 通用”，找到“AI Agent”，打开开关后填写：

| 字段 | 填写 |
| --- | --- |
| 提供方 | OpenAI Compatible |
| 模型 | 第 2 步记下的模型名称，必须完全一致 |
| API Key | 调用方的 API Key |
| Base URL | 网关访问地址加 `/v1`，例如 `http://10.0.0.5:30080/v1` |

“最大 Token 数”保持默认即可，保存。如果 AI 设置由配置文件管理，这里是只读的，需要改配置文件。

Base URL 必须带 `/v1`：AI 助手会在它后面拼 `/chat/completions`，而网关的接口是 `/v1/chat/completions`。

## 额度和限速

AI 助手此后就是这个调用方：它的每次请求都计入该调用方的“每分钟 Token 上限”和“总额度”，也出现在“用量”页面里。额度用完或超过限速时，AI 助手的请求会被网关拒绝，对话里会看到错误。所以建议像上面那样给 AI 助手单独建一个调用方，不要和业务共用。

## 怎么确认可用

打开 AI 助手，让它做一件需要工具的事，例如“列出异常的 Pod”。能看到它调用工具并给出基于真实数据的回答，就说明可用。同时可以在“用量”页面里看到该调用方的用量增加。

## 常见问题

- **工具调用没打开**：模型只会回答文字，不调用任何工具，或者对话直接报错。按第 1 步检查“工具调用解析器”是否已填写并且服务已重建完成。
- **401 / 403 或被拒绝**：API Key 填错，或调用方没有被授权访问该模型，或调用方被停用。
- **429 或额度提示**：触发了调用方的限速或总额度，在调用方列表里调整。
- **连不上**：Base URL 缺少 `/v1`，或 MPlatform 服务端访问不到节点地址和 NodePort。
- **找不到模型**：“模型”字段与发布时的模型名称不一致，或服务已取消发布。
